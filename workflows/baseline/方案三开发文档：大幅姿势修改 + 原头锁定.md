# 方案三开发文档：大幅姿势修改 + 原头锁定

## 1. 文档目的

解决方案二难以处理的大幅姿势变化。

目标：

> 即使身体姿势发生明显改变，仍最大程度保持原始角色头部身份。

推荐名称：

`03_WAI_大幅姿势_原头锁定.json`

---

# 2. 使用场景

该工作流仅在以下情况启用：

```text
站立 → 坐下
站立 → 蹲姿
站立 → 跪姿
正面 → 明显侧身
身体大幅扭转
双臂大幅改变
镜头角度明显变化
```

如果只是：

```text
换衣服
小幅手部动作
普通站姿变化
```

优先使用方案一或方案二。

---

# 3. 核心思想

方案三不要求 AI “重新生成一张完全相同的脸”。

而采用：

```text
原始头部直接保留
+
身体重新生成
+
最后重新组合
```

核心原则：

> 能复制原图像素，就不依赖模型重新记忆。

---

# 4. 整体架构

```text
                    原人物图
                       │
          ┌────────────┴────────────┐
          │                         │
          ↓                         ↓
     Head Mask                 Body Source
          │                         │
          ↓                         ↓
    Crop Original Head         Body Inpaint
          │                         │
          │                    ControlNet
          │                         │
          │                    新姿势身体
          │                         │
          └────────────┬────────────┘
                       ↓
                Image Composite
                       ↓
                Neck / Hair Seam
                    Inpaint
                       ↓
                  Final Image
```

---

# 5. 三阶段开发

方案三必须拆成三个阶段。

## Stage A

生成新的：

```text
身体
姿势
服装
```

暂时不追求头部完全正确。

## Stage B

将：

```text
原始头部
```

重新合成到新身体。

## Stage C

只修补：

```text
脖颈
下巴边缘
头发边缘
肩部
衣领
```

---

# 6. 原始头部区域

建立：

```text
HEAD MASK
```

应包含：

```text
完整脸部
完整头发主体
耳朵
头顶
下巴
部分脖颈
```

推荐留出安全边界。

原始头部不是：

```text
只裁脸
```

而是：

```text
脸 + 头发 + 必要头颈区域
```

因为发型也是人物身份的重要组成部分。

---

# 7. 头部 Mask 类型

需要两个 Mask：

```text
Head Keep Mask
Head Blend Mask
```

## Head Keep Mask

用于保持：

```text
脸
五官
头发主体
```

边缘较硬。

## Head Blend Mask

用于融合：

```text
下巴
脖子
发尾
肩部
衣领
```

边缘更柔和。

---

# 8. 新身体生成

身体生成部分基本继承方案二：

```text
WAI
+
Inpaint
+
DWPose
+
OpenPose ControlNet
```

区别：

> 允许身体区域使用更高 Denoise。

---

# 9. 身体采样参数

建议：

```text
Steps: 24–30
CFG: 5
Sampler: euler_ancestral
Scheduler: normal
```

Denoise：

```text
0.40–0.60
```

默认：

```text
0.48
```

因为方案三允许真正重新构造身体姿势。

---

# 10. OpenPose 参数

推荐：

```text
Strength = 0.75
Start = 0.00
End = 0.80
```

根据姿势测试：

```text
0.65
0.75
0.85
```

对于大姿势：

可以比方案二更积极使用 ControlNet。

---

# 11. 新身体必须继续锁定体型

Prompt 永久保持：

```text
same body type,
tall slender woman,
long legs,
slim waist,
narrow shoulders,
slender arms,
delicate proportions,
pale skin
```

重点是：

```text
same body type
```

而不是要求：

```text
same pose
```

---

# 12. 合成阶段

生成新身体后：

```text
Original Head
+
Generated Body
↓
Image Composite
```

原始头部覆盖 AI 新生成头部。

此时可能出现：

```text
脖子位置不对
发尾断裂
肩膀接不上
衣领穿帮
光线不一致
```

这些问题不通过重新生成脸解决。

---

# 13. 接缝修复

建立：

```text
SEAM MASK
```

只能覆盖：

```text
下巴边缘
脖子
头发最外围
肩部少量区域
衣领
```

绝不能覆盖：

```text
眼睛
鼻子
嘴
脸部中心
头发主体
```

---

# 14. 接缝 Inpaint 参数

建议：

```text
Steps: 10–16
CFG: 4–5
Denoise: 0.12–0.25
```

默认：

```text
Steps = 12
CFG = 4.5
Denoise = 0.18
```

这里恰好可以继承当前基线第二遍采样思想。

---

# 15. 头部朝向问题

这是方案三最大的限制。

如果：

```text
原图头部正面
```

而目标：

```text
完全侧脸
```

则不能直接把原头贴回。

因此方案三分：

## 3A 原头完全锁定

要求：

```text
头部角度基本不变
```

身体可以大幅变化。

这是主要版本。

## 3B 头部允许轻度重构

未来扩展：

```text
IPAdapter Face
或
角色 LoRA
```

用于生成不同角度的同一人物头部。

3B 不属于第一阶段开发范围。

---

# 16. 身材稳定策略

大幅改变姿势时无法像素级保持身体。

因此需要建立身体比例验收：

记录原人物：

```text
头身比
肩宽视觉比例
腰宽视觉比例
臀腰关系
腿部长度比例
手臂纤细程度
```

生成图必须保持相同视觉体型。

---

# 17. 肤色策略

新生成身体裸露皮肤必须使用固定提示：

```text
pale skin,
same skin tone,
consistent skin tone
```

同时降低：

```text
颜色漂移
强环境色污染
过强暖光
过强冷光
```

若出现：

```text
头部肤色
≠
身体肤色
```

优先局部修正身体皮肤。

禁止重新生成原脸来适配身体。

---

# 18. 光照一致性

由于原头直接来源于原图，大幅改变：

```text
场景
光源方向
昼夜
颜色温度
```

会导致合成感明显。

因此方案三第一阶段规定：

场景光照不得出现极端变化。

适合：

```text
白天 → 白天
室外 → 类似室外
柔和光 → 柔和光
```

暂不作为主要目标：

```text
白天 → 夜晚霓虹灯
正面光 → 极强逆光
蓝天 → 红色火光
```

# 22. 验收标准

头部：

- [ ] 原始五官保持
- [ ] 原眼睛保持
- [ ] 原发型主体保持
- [ ] 原头部视觉身份保持
- [ ] 头部不存在明显二次生成感

身体：

- [ ] 新姿势符合目标骨架
- [ ] 身材保持高挑纤细
- [ ] 腰宽无明显漂移
- [ ] 肩宽无明显漂移
- [ ] 腿长比例合理
- [ ] 肤色与原头一致

融合：

- [ ] 下巴无接缝
- [ ] 脖颈自然
- [ ] 发尾自然
- [ ] 衣领自然
- [ ] 肩部自然
- [ ] 无明显剪贴感

# 23. 失败回退规则

出现以下情况：

```text
头部角度与身体严重不匹配
```

回退方案二或者更换目标 Pose。

出现：

```text
身体比例漂移
```

降低：

```text
Denoise
```

并加强固定体型提示。

出现：

```text
姿势不服从
```

提高：

```text
ControlNet Strength
```

出现：

```text
接缝修补导致脸发生变化
```

立即缩小 Seam Mask。

---

# 24. 方案三定位

```text
人物身份保持：★★★★★
头部保持：★★★★★
服装自由度：★★★★★
身体姿势自由度：★★★★★
开发难度：★★★★☆
显存压力：★★★★☆
```

但存在一个明确限制：

> 原头方向与目标身体方向必须基本兼容。

方案三不是默认工作流，而是方案二不能满足大姿势变化时的增强版本。

---

# 25. 三方案关系

最终项目形成：

```text
当前基线
│
├── 方案一
│   └── 只换服装
│
├── 方案二
│   └── 姿势 + 服装
│       默认主力
│
└── 方案三
    └── 大姿势
        + 原头锁定
```

开发顺序：

```text
方案一
↓
方案二
↓
方案三
```

不要并行开发。

因为：

```text
方案一验证 Inpaint
方案二验证 Pose Control
方案三验证 Composite
```

每一级只增加一个主要变量，便于定位问题。
